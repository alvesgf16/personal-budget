# Clean Code inventory (PB-89 / PB-90)

Canonical inventory and enforcement pattern for [PB-89](https://alvesgf.atlassian.net/browse/PB-89).
Source: Robert C. Martin, _Clean Code_. Kickoff Task: [PB-90](https://alvesgf.atlassian.net/browse/PB-90).

**Tags:** `automate` (machine gate in `npm run lint` or another non-AI check), `guide` (Cursor / human judgment), `exception-candidate` (known or likely conflict with an existing PB convention — resolve in the child Task).

Chapter Tasks enable rules and write guidance. [PB-91](https://alvesgf.atlassian.net/browse/PB-91) enabled Ch.2 Meaningful Names automate rules and created `.cursor/rules/clean-code.mdc`. [PB-92](https://alvesgf.atlassian.net/browse/PB-92) enabled Ch.3 Functions book-metric gates and appended Functions guidance to that file.

**Batch size:** The usual ~200 authored-TS-line soft cap is **waived for the entire Clean Code epic** ([PB-89](https://alvesgf.atlassian.net/browse/PB-89)) — chapter Tasks (PB-91+) may exceed it when compliance fixes require it.

### Cursor rules convention

Do **not** create one `.mdc` per Clean Code chapter. Per-chapter files would scatter overlapping advice and drown always-apply context.

- Default: grow **one** `.cursor/rules/clean-code.mdc` for judgment-based Clean Code guidance as chapter Tasks land
- Split a new `.mdc` only when scope differs (e.g. `*.spec.ts` globs for unit-test guidance, or extending `.cursor/rules/document-store.mdc` for store boundaries)
- Guide-heavy chapters (Ch.1, 12, 14, much of 6/13) append short sections to the shared file rather than opening new ones
- Shared guidance file: `.cursor/rules/clean-code.mdc` (started in PB-91; later chapters append)
